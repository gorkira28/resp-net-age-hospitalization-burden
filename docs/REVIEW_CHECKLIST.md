# Review checklist

## Scientific review

- [ ] The research question is decision-relevant and clearly descriptive.
- [ ] Age groups are mutually exclusive; overlapping summary categories are excluded.
- [ ] Rates are described as RESP-NET surveillance-area estimates, not national estimates.
- [ ] The 85+ and infant rate-ratio comparisons are acceptable for the portfolio narrative.
- [ ] No causal, clinical-effectiveness, or hospital-quality claims are made.

## Code and reproducibility

- [ ] Python acquisition and analysis steps are understandable.
- [ ] SAS code is substantive and the SAS OnDemand run instructions are clear.
- [ ] QA report, tests, and combined-rate cross-check are sufficient.
- [ ] Dependencies and source URLs are documented.

## Presentation

- [ ] README can be understood by a recruiter within two minutes.
- [ ] Figures are legible and the caveats are visible.
- [ ] Portfolio case study reflects the most important analytical contribution.
- [ ] LinkedIn draft sounds like Kira and contains no unsupported statements.

## External actions requiring approval

- [ ] Create and push the public GitHub repository.
- [ ] Set repository description, homepage, and topics.
- [ ] Add the project to the GitHub profile README.
- [ ] Add the case study and preview image to the portfolio website.
- [ ] Change pinned repositories, if recommended.
- [ ] Post or schedule the LinkedIn draft.
